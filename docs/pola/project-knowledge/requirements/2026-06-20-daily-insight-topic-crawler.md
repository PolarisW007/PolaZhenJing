# 每日选题全网抓取需求

日期：2026-06-20

## 用户原始需求

用户指出当前“每日选题”不是从全网线上抓取，且内容像来自 AI 表格，要求参考 `last30days` skill 的抓取思路，并可从 PolaNews 提取对应周期内的数据。

## 目标

- 将洞察选题池从静态种子升级为可手动刷新的周期信号聚合。
- 来源至少覆盖 PolaNews 站内新闻数据和无需密钥的外部公开源。
- 每条选题必须带来源、证据链接、来源数量、评分和生成时间，避免“AI 表格拍脑袋”。
- 刷新失败不能影响既有选题列表、状态打标和一键导入上传。

## 目标用户

- 管理员：在 `/admin/insights/topics` 查看每日选题、刷新周期、判断证据、打标和导入上传。
- 后续文章作者：基于导入的选题模板写洞察文章。

## 范围

- 新增公开源采集器：PolaNews、Hacker News Algolia、GitHub Search、少量公开 RSS。
- 新增选题归一化：去重、标签识别、启发式评分、证据链接收敛。
- 新增选题刷新入口：管理员在选题页选择周期并刷新。
- 扩展 JSON 存储：记录刷新元数据和选题来源字段，兼容旧数组格式。

## 非目标

- 本次不接入需要登录态或付费 key 的 X/Twitter、TikTok、Instagram。
- 本次不自动定时运行 cron，只提供手动刷新；后续可接 systemd timer/cron。
- 本次不调用大模型生成选题，先保证可追溯数据源闭环。

## 验收标准

- A1 文档：需求、PRD/SPEC、SDD、开发日志记录当前实现、边界和风险。
- A2 数据源：刷新时可从 PolaNews API 和至少一个外部公开源采集信号；外部失败时页面不崩溃。
- A3 选题质量：生成的选题包含 `source_type`、`source_count`、`evidence_links`、`score`、`generated_at`。
- A4 状态兼容：已有 `selected/imported/archived` 状态不因刷新丢失。
- A5 UI：选题页展示刷新按钮、周期、最近刷新摘要和每条选题的来源/分数/证据链接。
- A6 导入：刷新生成的选题仍可一键导入上传页，Markdown 草稿包含证据链接。
- A7 测试：新增单测覆盖 PolaNews 解析、信号转选题、刷新合并、UI 刷新入口。
- A8 回归：既有工作台、筛选、状态打标、导入上传路径保持可用。

## 风险等级

P2。涉及外部请求和生产后台主流程，但不涉及 secret、数据库迁移或自动后台任务。需要超时、条数限制、失败隔离和日志脱敏。
