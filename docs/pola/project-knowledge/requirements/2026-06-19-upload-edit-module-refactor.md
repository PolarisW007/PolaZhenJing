# 需求记录：上传与编辑模块系统性重构

日期：2026-06-19

## 用户原始需求

用户确认上传和编辑模块目前“小问题太多”，要求阅读历史需求文档并结合当前代码，整体重构上传（upload）和修改（edit）模块。重点要求：

- 解决高耦合、低内聚问题。
- 覆盖并保持现有 AI 功能。
- 提升系统可读性、易用性和健壮性。
- 按 Pola A2A 流程重写 PRD、SDD、SPEC，并在确认后实施。
- 必须有 Harness 校验。

用户已确认四个关键方案决策：

1. 已有 `.md` 文章编辑页默认打开 Markdown 模式，富文本作为可切换视图。
2. 编辑页 AI 改写率默认 `50%`，仅在填写“修改建议简述”时触发 AI；未填写时普通保存不调用 AI。
3. 分阶段抽服务，不做一次性大爆破，保留 `app/uploader.py` 路由兼容。
4. 预览走“保存等价管线”，不再允许 raw HTML 直接作为预览结果。

## 目标

- 将上传、编辑、预览、保存、AI 改写、图片本地化统一到 canonical Markdown 管线。
- 让富文本和 Markdown 双模式切换内容稳定、段落清晰、图片不丢失。
- 让编辑页“修改建议简述”和 AI 改写率可用且可测试。
- 把 `app/uploader.py` 中高度耦合的文章生产逻辑分层，降低后续维护成本。
- 保持现有文章、短链、分享卡片、多平台同步发布和公开阅读链路不回归。

## 目标用户

- 管理员：上传文章、粘贴富文本、上传文件、输入 URL、选择 AI 改写率、生成图片、编辑旧文章、填写修改建议、预览、保存、同步发布。
- 普通用户：阅读公开文章。本次不改变普通阅读入口，只确保文章保存后仍可正常阅读。

## 范围

- `/PolaZhenjing/admin/upload`
- `/PolaZhenjing/admin/articles/<filename>/edit`
- `/PolaZhenjing/admin/articles/<filename>/preview`
- 上传和编辑共用的正文转换、预览、图片、本地化、AI 修订服务。
- 相关单测、浏览器 Harness、项目文档与开发日志。

## 非目标

- 不重做公开文章详情页 UI。
- 不重构 `app/social_publish.py` 多平台发布中心，只保证其继续读取稳定 Markdown。
- 不改变 `_posts/*.md` 的文件存储模式。
- 不新增数据库 schema。
- 不改生产 nginx/systemd 配置，除非后续部署验证另行确认。

## 现状和问题

| 问题 | 现状证据 | 影响 |
| --- | --- | --- |
| 模块过大 | `app/uploader.py` 约 3500 行，包含上传、编辑、文章展示、分享、GEO、同步发布入口等 | 改一个编辑问题容易牵连多个链路 |
| 编辑器重复实现 | `upload.html` 和 `article_edit.html` 各自维护 TinyMCE/Markdown 切换逻辑 | 行为不一致，bug 修复重复 |
| 富文本和 Markdown 无统一模型 | 历史 2026-06-08 方案为“后端零改动”，富文本预览直出 HTML | 切换、预览、保存语义不一致 |
| AI 修订输入不稳定 | 编辑保存时修改建议可能基于 raw HTML 或污染内容执行 | 保存失败、重复段落、格式错乱 |
| 预览不等于保存 | 当前富文本预览和保存使用不同路径 | 用户看到的预览与最终文章不一致 |

## 保持的 AI 功能

- 上传页 AI 改写率：`0/25/50/75/100`。
- 上传页标题、摘要、标签生成。
- 上传页风格化改写和图片生成/插图。
- 上传页富文本粘贴图片上传、本地化、远程图片处理。
- 编辑页修改建议简述。
- 编辑页 AI 改写率。
- 自动标签、阅读时间、短链、分享卡片、多平台同步发布依赖的 Markdown 输出。

## 验收标准

- A1 文档：本次重构有 requirement、PRD、SDD、SPEC、devlog 和测试报告。
- A2 架构：上传/编辑正文处理抽出服务层，路由保持兼容，`app/uploader.py` 不再新增核心正文转换逻辑。
- A3 转换：Markdown -> 富文本、富文本 -> Markdown 切换不丢失主要段落、图片、链接。
- A4 预览：上传和编辑预览均走保存等价管线，不显示 raw Markdown 图片语法。
- A5 保存：编辑页普通保存成功，保存后文章详情页展示更新。
- A6 AI 修订：填写修改建议时先转 canonical Markdown 再调用 AI；未填写时不调用 AI。
- A7 AI 改写率：上传和编辑均支持 `0/25/50/75/100`，0% 不改写正文。
- A8 图片：富文本粘贴图片、已有本地图片、远程图片本地化不回归。
- A9 兼容：文章列表、公开文章、短链、分享卡片、多平台同步发布读取文章不回归。
- A10 测试：相关 pytest、py_compile、git diff 检查和浏览器 Harness 有证据。

## 风险

- R1 历史文章格式不统一，转换时需避免大规模重写旧文章。
- R2 富文本 HTML 转 Markdown 可能无法 100% 保留复杂样式，本次优先保留语义内容、图片、链接、表格。
- R3 AI 输出不确定，需要测试中 monkeypatch，线上保留失败降级。
- R4 当前工作区已有大量用户/历史改动，本次提交必须只收敛相关文件。
