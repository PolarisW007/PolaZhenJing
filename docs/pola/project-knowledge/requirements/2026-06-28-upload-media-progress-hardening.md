# 需求记录: 上传媒体与 PDF 进度修复

## 原始需求

用户反馈线上云服务器文章和上传页存在三类问题:

- `claude-code-cli-60-20260628.md` 生成后,原文图片没有在文章中展示,页面只出现残缺的 Markdown 图片标记。
- `/PolaZhenjing/admin/upload` 上传 PDF 时没有进度提示,页面像假死。
- 上传页富文本编辑器中粘贴的图片没有展示。

## 目标

- 富文本粘贴/拖入图片后,优先上传到服务器并用稳定本地 URL 回填编辑器。
- 服务端保存富文本时不能再产生 `![alt]()` 或 `blob:` 这类不可渲染图片语法。
- 文件/PDF 上传期间展示明确进度、处理中状态和失败反馈。
- 保持现有上传文件、粘贴内容、URL、AI 改写率、原文媒体保留、风格选择流程不变。

## 边界

- 本轮只修上传/富文本媒体链路和进度体验。
- 不重构整套上传模块,不改变 AI 生成图、社媒发布、文章列表和权限逻辑。
- 线上已有坏文章需要从云服务器源文件/草稿/资源目录定位原图后才能恢复;本地工作区没有该文章源文件。

## 验收标准

- 富文本 HTML 中空 `src`、缺失 `src`、`blob:` 图片不会保存成坏 Markdown。
- 已上传富文本图片返回 `/PolaZhenjing/assets/images/richtext/...` 稳定路径。
- 上传页 HTML 包含文件上传进度条、`xhr.upload.onprogress` 和上传中按钮锁定逻辑。
- 粘贴表单提交前会等待 TinyMCE 图片上传完成,失败时阻止提交并提示。
- 历史文章中已经存在的裸图片占位 `![alt]` 或空链接 `![alt]()` 不再在文章页露出为正文文本。
- 相关 Python 单测、语法检查和 harness 文档通过或记录阻塞原因。

## 风险等级

P2。原因: 涉及上传、媒体文件、富文本保存和用户主流程。需要保留既有入口兼容,并避免无界网络/文件行为。本轮不增加新的后台任务或大文件处理上限。
