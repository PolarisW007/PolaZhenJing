# 2026-07-03 历史每日选题回填与云端安全合并需求

## 背景

云服务器上的 PolaZhenJing 没有同步到 GitHub 最新版本，且每日选题池未覆盖 2026-06-01 到 2026-07-03 的完整历史日期。线上仓库同时存在本地提交和未提交运行数据，直接 `git pull` 会触发多文件冲突，存在覆盖文章、图片、选题池和运行配置的风险。

## 风险等级

P1。原因：本次涉及生产仓库分叉合并、数据文件 `data/insight_topics.json` 回填、服务重启和线上选题主流程。必须先备份、可回滚、再执行。

## 目标

1. 提供一个可重复执行的历史日期补全生成能力。
2. 覆盖 2026-06-01 至 2026-07-03，每个日期至少存在 1 条每日洞察选题。
3. 在云端安全合并 GitHub 最新代码与服务器文章/运行数据，避免硬重置或覆盖用户已有内容。
4. 保持 `/admin/workbench`、`/admin/insights/topics`、导入上传、文章查看、登录态等旧路径不回归。

## 边界

- 回填只补缺失日期；已有日期的选题、状态和底稿不覆盖。
- 本次不重写每日选题 UI，不新增自动定时任务。
- 本次不生成正式文章 `_posts`，只回填选题池。
- 本次不迁移密钥、不打印密钥、不提交 `.env`。

## 验收标准

- A1：`2026-06-01` 至 `2026-07-03` 的 33 个日期，在选题池中每日至少有 1 条 topic。
- A2：重复执行历史回填不会为已覆盖日期重复生成，也不会覆盖 `selected`、`imported`、`archived` 或人工维护状态。
- A3：提供 CLI dry-run 与持久化执行模式，输出 `missing_days_before`、`added_dates`、`missing_days_after`、`total_topics`。
- A4：回填生成的 topic 保持长底稿能力，`draft_word_count >= 4500`，并可沿用现有导入上传流程。
- A5：云端合并必须先创建备份分支和文件备份，合并前有演练或等价验证，禁止直接硬重置生产目录。
- A6：本地测试、A2A function test cases harness、`git diff --check` 通过后再推送和云端执行。
- A7：实现不得引入无界后台任务、网络抓取、CPU/I/O 密集循环或 secret 输出。
- A8：生产部署后验证服务存活、管理入口、选题入口和历史数据仍可访问。
