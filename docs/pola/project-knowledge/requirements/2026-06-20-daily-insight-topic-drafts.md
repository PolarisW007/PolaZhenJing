# 每日选题 5000 字底稿需求

日期：2026-06-20

## 用户原始需求

用户反馈每日选题列表中每篇选题需要包含生成的约 5000 字底稿；列表不展示全文，只展示摘要；点击“一键导入上传”后，底稿内容也必须同步预输入到上传页的 Markdown 编辑器。目前只导入了轻量提纲，未导入完整底稿。

补充反馈：线上点击“一键导入上传”后，上传页仍然显示空的富文本编辑器，具体 Markdown 内容没有进入可编辑区域；同时钉钉底料入口已无使用价值，需要从当前工作台和选题页去除。

补充反馈 2026-06-21：洞察选题列表红框区域只需要显示文章的具体摘要内容，不需要展示从哪里导入、证据、评分、标签、底稿字数等运营信息；“一键导入上传”进入 upload 后，正文编辑器也只预填具体摘要内容，不再把来源、证据、状态和其他不相关信息写入正文。

补充反馈 2026-06-24：线上 `?insight_topic=724e49daee3e` 导入上传页只出现一句摘要，没有 5000-30000 字文章底稿。需要修正为“选题列表只展示摘要，但一键导入上传必须预填可直接编辑的长文章底稿”，同时仍不能把状态、来源、评分等运营元信息写入正文。

## 目标

- 每条洞察选题在数据层都有可导入的长底稿 Markdown。
- 选题列表保持扫描友好，卡片正文区只展示具体摘要，不展示来源、证据、评分、标签和底稿字数。
- 一键导入上传页后，上传页默认进入 Markdown 源码模式，并将 5000-30000 可见字符的正文型长稿预填到正文编辑器。
- 导入选题时不再预加载空富文本编辑器，避免 TinyMCE 抢占 Markdown 可见区域。
- 兼容旧 `data/insight_topics.json`：旧选题缺少底稿时自动补齐。
- 当前 UI 不再展示钉钉底料入口和“从钉钉底料补充”的空态提示。

## 范围

- 扩展 `app/insight_topics.py` 的选题 normalize、线上信号转选题和上传预填逻辑。
- 扩展 `/admin/insights/topics` 选题列表展示摘要-only 卡片正文。
- 扩展测试，覆盖默认选题、刷新选题、列表摘要-only、导入上传长稿预填路径。

## 非目标

- 本次不引入额外 LLM 调用，避免刷新选题依赖密钥、变慢或产生费用。
- 本次不在列表页展示 5000 字全文。
- 本次不新增定时任务或后台队列。

## 验收标准

- A1 文档：需求、PRD/SPEC、SDD、开发日志和 delivery 状态记录完整。
- A2 数据：`load_topics()` 返回的每条选题都包含 `draft_markdown` 和 `draft_word_count`。
- A3 长度：自动生成的底稿可达到约 5000 字规模，至少不低于 4500 个可见字符。
- A4 列表：选题列表卡片正文区只展示摘要，不展示来源、证据、评分、标签、底稿字数或完整底稿。
- A5 导入：一键导入上传后，上传页 Markdown textarea 包含 5000-30000 可见字符的文章长稿和正文章节，不包含来源、证据链接、状态、评分等选题池管理元信息。
- A6 兼容：旧 JSON、默认种子和刷新生成的选题都能补齐底稿，不破坏状态打标。
- A7 测试：最小相关 pytest、语法检查和 function test cases harness 通过。
- A8 回归：工作台、选题刷新、状态保存、上传预填旧路径保持可用。
- A9 导入页：浏览器中 `#content` Markdown textarea 可见且包含文章长稿，`#rich-content` 默认隐藏，TinyMCE 不在导入状态下抢占编辑区。
- A10 去钉钉底料：工作台、选题页、空态和相关测试不再要求展示钉钉底料入口。

## 风险等级

P2。涉及后台内容生成和上传主流程，但不新增生产配置、secret、数据库迁移或自动任务。主要风险是列表混入长稿、上传页只导入摘要或上传正文混入运营元信息；通过“列表摘要-only、upload 长稿正文-only”的边界降低风险。
