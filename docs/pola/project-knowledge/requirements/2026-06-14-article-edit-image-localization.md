# Requirement: 文章编辑后图片失效修复

日期: 2026-06-14

## 用户原始需求

用户反馈 `https://aipd.me/articles/rolling-ai-fde-ai-20260607.md` 编辑后所有正文图片失效,要求检查问题出在哪里并修复。

## 问题现象

- 文章列表仍能显示卡片和摘要。
- 文章详情页正文图片显示为 broken image。
- 线上文章正文被保存为大段富文本 HTML,包含钉钉文档临时图片地址和 `data-clipboard-cangjie` 等内部剪贴板属性。
- 外部图片 URL 在浏览器 GET 时会跳转到 `noAuth.png` 或返回 403,无法作为长期文章素材使用。

## 目标

- 定位并修复文章编辑保存链路,避免富文本编辑后把第三方临时图片和大体积剪贴板属性写入 `_posts`。
- 修复指定线上文章的失效图片,恢复可阅读状态。
- 保持上传页、文章编辑页、Markdown 模式和现有短链/分享逻辑可用。

## 非目标

- 不重做 TinyMCE 编辑器交互。
- 不迁移所有历史文章图片。
- 不新增第三方对象存储或图片 CDN。
- 不修改微信公众号或 X 发布逻辑。

## 验收标准

- A1 需求/架构/开发日志记录本次根因、方案、风险和验证结果。
- A2 富文本编辑保存时,服务端会清理富文本 HTML 中的大体积剪贴板属性和危险属性。
- A3 富文本编辑保存时,外部 http/https 图片会在安全校验后下载到本地 `assets/images/richtext/YYYY-MM/`,正文改写为本地资源 URL。
- A4 Markdown 模式仍支持原 Markdown 图片,不会被误删。
- A5 指定线上文章不再引用 `alidocs.dingtalk.com` 临时图片,正文图片请求返回 200 且为 image content type。
- A6 增加自动化测试覆盖富文本保存清洗和图片本地化回归。
- A7 发布前后有备份、验证和回滚说明。

## 风险等级

P2。影响生产文章阅读和文章编辑数据质量,涉及线上 `_posts` 文件和本地图片存储,但不涉及密钥、数据库 schema 或用户身份数据。
