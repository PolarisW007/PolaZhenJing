# 需求记录：上传页富文本编辑器稳定性修复

日期：2026-06-02

## 原始需求

用户反馈 `https://aipd.me/PolaZhenjing/admin/upload` 的粘贴内容富文本编辑器经常加载很慢或加载不出来，希望检查问题并升级修复。

## 目标

- 定位上传页富文本编辑器加载慢/不加载的根因。
- 移除会阻塞编辑器初始化的外部 CDN 依赖。
- 让富文本编辑器稳定、快速加载，并保留图片粘贴上传能力。
- 保留 Markdown 源码模式和基础文本框兜底。

## 非目标

- 不重做上传页整体交互。
- 不替换富文本编辑器品牌或重写编辑器能力。
- 不修改文章生成、风格选择和 LLM 重写流程。
- 不处理文章编辑页 EasyMDE CDN，本次只针对用户指出的上传页富文本编辑器。

## 验收标准

- A1 文档：需求、PRD/SDD、开发日志和发布记录覆盖本次修复。
- A2 根因：记录外部 CDN/字体 CSS 阻塞和 autoresize 高度异常的证据。
- A3 资源本地化：上传页不再引用 `cdn.jsdelivr.net/npm/tinymce`，TinyMCE 资源由 `/assets/vendor/tinymce/` 提供。
- A4 非阻塞：后台基础字体 CSS 不再阻塞脚本执行。
- A5 UI：富文本编辑器在浏览器中可见，初始高度稳定，不再撑出超大空白区域。
- A6 兜底：TinyMCE 初始化失败时保留基础文本框并提示用户仍可提交。
- A7 测试：相关单测、语法检查和浏览器 smoke 通过。

## 风险

- R1 本地 vendor TinyMCE 需要和模板插件列表保持同步。
- R2 如果后续上传页新增 TinyMCE 插件，需要同步补充对应本地插件文件。
- R3 字体改为非阻塞加载后，首次渲染可能先使用系统字体，再切换到 Noto Serif SC。
