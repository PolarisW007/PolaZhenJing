# 需求记录：X 自动发布

日期：2026-05-31

## 原始需求

用户确认“小红书不用实现了”，优先把 PolaZhenJing 文章同步发布到 X。

## 目标

- 在现有多平台发布中心增加 X 平台。
- 管理员可在单篇文章发布页点击“发布到 X”，系统通过 X 官方 API 创建 post。
- 发布内容包含文章标题、摘要和公网原文链接；如文章有本地封面图，优先上传并绑定到 X post。
- 同一篇文章已有成功 X 发布记录时，系统自动跳过，避免重复发送。
- X 凭据仅从服务端环境变量读取，不进入页面、数据库 payload、日志或 git。

## 边界

- 本次不实现小红书。
- 本次不实现 X OAuth 网页授权流程，先使用服务端环境变量 `X_USER_ACCESS_TOKEN` 管理用户访问令牌。
- 本次不批量群发到 X；先完成单篇文章的可验证自动发布能力。
- 本次不保存 refresh token，不在数据库中存储 X 访问令牌。

## 验收标准

- A1 文档：需求、PRD/SDD、架构记录和开发日志覆盖 X 自动发布方案。
- A2 后台入口：发布中心列表和单篇发布页展示 X 状态。
- A3 配置状态：未配置 `X_USER_ACCESS_TOKEN` 时，页面明确提示并能记录 `not_configured` 状态。
- A4 官方 API：配置 token 后，单篇文章可通过 X API 创建 post，并记录 post id 和外部链接。
- A5 去重：同一 `filename + platform=x` 已有 `posted` 成功记录时，后续发布任务标记为 `skipped_duplicate`。
- A6 安全：X token 不出现在页面、数据库 payload、日志、测试输出和 git diff。
- A7 测试：X 文案生成、配置读取和发布中心既有测试通过。

## 风险

- R1 X API 访问受开发者账号权限、应用计划、OAuth scope 和额度限制影响。
- R2 X 文本长度规则存在官方加权计数细节，本次以 280 字符保守截断，复杂场景后续可接入 twitter-text 类库。
- R3 媒体上传依赖 X 当前账号权限；图片上传失败会导致发布任务失败并落库，便于重试。
