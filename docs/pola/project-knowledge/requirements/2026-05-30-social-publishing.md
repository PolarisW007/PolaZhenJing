# 需求记录：文章多平台同步发布

日期：2026-05-30

## 原始需求

用户希望 PolaZhenJing 生成的文章具备一键同步发布到微信公众号、小红书、今日头条的能力。经调研确认，微信公众号有公开官方接口；小红书和今日头条暂未确认存在可直接用于普通内容账号的稳定公开发布 API。

## 目标

- 在文章后台为每篇文章提供统一的多平台发布入口。
- 微信公众号优先接入官方 API，支持同步到草稿箱，并预留确认发布能力。
- 小红书和今日头条第一阶段生成发布包，降低人工复制成本，后续等官方授权/接口明确后替换为自动 adapter。
- 记录每次发布状态、平台返回 ID、外部 URL、错误信息和操作轨迹。

## 边界

- 本次不绕过平台规则，不采集或保存浏览器 Cookie。
- 本次不做小红书/今日头条浏览器自动发布。
- 本次不自动群发微信公众号文章，默认先进入公众号草稿箱。
- 第三方平台凭据只从服务端环境变量读取，不进入前端页面、日志和 git。

## 验收标准

- A1 文档：需求、PRD/SDD、架构记录和开发日志覆盖本次多平台发布方案。
- A2 微信：在配置 `WECHAT_MP_APP_ID`、`WECHAT_MP_APP_SECRET`、IP 白名单后，文章可调用官方接口同步到公众号草稿箱。
- A3 发布包：未配置或不支持官方 API 的平台可生成标题、正文、摘要、标签、封面和操作提示。
- A4 后台：文章列表和文章详情能进入发布中心，展示三平台状态。
- A5 状态：每次发布/发布包生成写入 SQLite，含平台、状态、外部 ID/URL、错误和更新时间。
- A6 安全：AppSecret、access_token、Cookie 不出现在页面、数据库 payload、日志或测试输出中。
- A7 验证：Python 语法检查和核心发布包单测通过。

## 风险

- R1 微信接口权限可能受公众号类型、认证状态、接口权限、IP 白名单影响。
- R2 微信正文图片必须上传到微信图文图片接口，外链图片可能被过滤。
- R3 小红书/今日头条官方内容发布权限不稳定，第一阶段只能做半自动发布包。
- R4 当前文章生成任务会自动 `git add -A`，后续应单独治理，避免发布模块改动被文章生成流程误带入。
