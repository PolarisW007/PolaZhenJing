# SPEC：每日选题 5000 字底稿

日期：2026-06-20

## 字段

每条 topic 标准字段新增：

- `draft_markdown: string`：完整 Markdown 底稿。
- `draft_word_count: number`：底稿可见字符数。

兼容策略：

- `_normalize_topic()` 在字段缺失时调用生成器补齐。
- `save_topics()` 继续通过 normalize 持久化新增字段。
- 旧数组格式和旧字段不变。

## 底稿生成规则

- 输入：标题、角度、摘要、标签、来源类型、评分、证据链接。
- 输出：Markdown 长文草稿，包含导语、核心判断、证据、行业影响、产品/工程启发、反例与风险、写作收束。
- 长度：目标 5000 可见字符，最小 4500，可控上限约 5600。
- 不调用外部 LLM；采用确定性结构化生成，避免刷新链路变慢或依赖 key。

## UI

- 列表卡片正文区只展示 `summary`。
- 列表不展示 `source_type`、`source_count`、`score`、`evidence_links`、`tags`、`draft_word_count`。
- 列表不输出 `draft_markdown`。
- 导入上传时 `build_upload_prefill()` 的 `content` 使用 `draft_markdown` 派生出的正文型长稿；缺失或过短时重新生成底稿后再派生。
- 正文型长稿从 `## 导语` 起保留正文章节，并保留标题；不包含 `## 洞察选题`、`## 写作角度`、`## 证据链接` 以及来源、证据链接、状态、评分等选题池管理元信息。
- 正文型长稿目标为 5000-30000 可见字符；若剔除管理元信息后不足 5000，则追加 upload 专用正文延展段。
- 导入上传时默认 Markdown 源码模式：
  - `#content` textarea 必须可见并承载预填长稿。
  - `#rich-content` 默认隐藏。
  - 页面不主动初始化 TinyMCE；只有用户手动切到富文本时再加载并转换。
- 工作台和选题页不再展示钉钉底料入口，空态提示改为刷新线上选题。

## 测试用例

- 默认选题 load 后存在底稿字段。
- 刷新生成选题后存在底稿字段。
- 导入上传页 textarea 中出现 5000-30000 可见字符长稿，包含 `## 核心判断` 等正文章节，且不包含来源、证据链接和选题池管理章节。
- 列表页显示摘要，但不包含来源、评分、证据链接、标签、底稿字数和底稿独有章节全文。
- Playwright 验证导入上传页 Markdown textarea 可见、富文本隐藏、TinyMCE 未加载、textarea 中不是摘要-only 内容。
- 工作台和选题页 HTML 不包含“钉钉底料”。
