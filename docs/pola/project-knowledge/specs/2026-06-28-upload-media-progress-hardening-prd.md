# PRD: 上传媒体与 PDF 进度修复

## 用户流程

### 文件/PDF 上传

1. 管理员进入 `/PolaZhenjing/admin/upload`。
2. 切换到“上传文件”,选择或拖入 PDF/Word/HTML/Markdown。
3. 点击“下一步:选择风格”。
4. 页面显示上传进度条:
   - 浏览器能计算文件上传进度时显示百分比。
   - 上传完成但服务端仍在解析 PDF/文档时显示“正在解析文件”。
   - 成功后进入风格选择页。
   - 失败时留在当前页并展示错误。

### 富文本粘贴图片

1. 管理员在“粘贴内容”的富文本模式粘贴网页、文档或图片。
2. TinyMCE 能处理的 base64/blob 图片在提交前上传到 `/admin/upload/media`。
3. 上传成功后编辑器中的图片 `src` 改为稳定本地资源 URL。
4. 如果图片上传失败,本次提交停止并提示用户改用插入配图或重试。

### 文章生成

1. 服务端把富文本转换为 canonical Markdown。
2. 只有具备可访问 `src` 的图片会进入 Markdown。
3. 空 `src`、缺失 `src`、`blob:` 图片不会写成坏的 `![alt]()`。
4. 文章详情页渲染历史 Markdown 时会过滤裸图片占位,正常 `![alt](/path)` 图片仍保留。

## 权限与状态

- 仅管理员上传页可用。
- 未登录仍按原逻辑跳转登录。
- 文件大小仍受现有 16MB 限制。
- 媒体保留/去除、AI 改写率、标题/标签/描述字段保持原有行为。

## 空态与异常

- 未选择文件: 使用浏览器原有表单校验或后端原错误提示。
- 上传失败: 进度区域显示失败原因并恢复提交按钮。
- 图片上传失败: 富文本状态提示失败,不进入风格选择。
- 服务端无法恢复历史坏文章原图: 不自动猜测图片,需到云服务器定位原始资源;页面至少不再显示坏图片占位文本。

## 非目标

- 不新增断点续传。
- 不新增 PDF 解析后台 job。
- 不替换 TinyMCE。
- 不在本轮自动修复云端所有历史坏文章。
