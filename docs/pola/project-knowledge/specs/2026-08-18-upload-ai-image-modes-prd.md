# PRD/SPEC：上传文章 AI 生图四档模式

日期：2026-08-18

## 1. 产品目标

让内容发布者在文章生成前直接控制 AI 配图密度，在等待时间、调用成本与视觉丰富度之间做清晰选择，并保留现有文章生成主流程。

## 2. 模式规格

| 模式值 | 页面名称 | AI 尝试数量 | 段落选择 | 默认 |
| --- | --- | --- | --- | --- |
| `cover` | 只生成题图 | 1 张 | 无正文图 | 否 |
| `summary` | 概括 | 3 张（1+2） | 在全文均匀选择 2 个代表段落 | 否 |
| `standard` | 适中 | 5 张（1+4） | 选择 4 个核心观点段落 | 是 |
| `detailed` | 详细 | 1+N 张 | 每个可配图正文段落，N ≤ 12 | 否 |

成功数量可能因外部 API 失败少于尝试数量。用户上传配图和原文媒体不计入上表。

## 3. 用户流程与状态

1. 管理员打开上传页，在任一输入 Tab 准备文章。
2. 在“AI 生图模式”区域选择一档；若不操作则为“适中”。
3. 提交后进入既有风格选择页，生图模式不在第二页重复编辑。
4. 点击生成后，后台先完成文本处理，再按模式规划题图和正文图。
5. 进度页显示“正在按「模式名」生成 AI 插画”。
6. 成功时显示实际生成数量；部分/全部失败时显示降级提示，文章仍进入既有完成态。
7. 用户可从风格页返回上传页重新选择；已被读取并删除的 draft 不提供恢复，本次保持现状。

## 4. 页面规格

### 4.1 AI 生图模式模块

- 字段名：`image_generation_mode`。
- 控件：radio 卡片，不允许多选。
- 选项文案：
  - 只生成题图：`1 张 · 文章封面`。
  - 概括：`3 张 · 题图 + 全文概括`。
  - 适中：`5 张 · 题图 + 核心观点`。
  - 详细：`逐段配图 · 最多 12 段`。
- 帮助文案：“数量包含题图；手动配图和原文图片不计入 AI 数量。详细模式按正文段落生成，最多 12 张段落图。”
- 默认：`standard`。
- 布局：≥ 900px 四列；560–899px 两列；< 560px 单列。

### 4.2 加载、错误和完成态

- 提交：沿用原按钮禁用和任务提交反馈。
- 生成中：任务阶段含模式名，不展示敏感 prompt 或 provider 信息。
- 部分失败：warning 提示实际生成张数，仍使用成功图片排版。
- 全部失败：warning 提示文章将不含 AI 插图；原文/用户图片仍可保留。
- 超限：详细模式只规划前 12 个按全文均匀分布的正文段落，任务消息提示安全上限（若发生）。

## 5. 正文段落定义

详细模式的正文段落由 Markdown 空行分块后判断。以下内容不单独生成正文图：

- Markdown 标题。
- 围栏代码块、纯行内代码块。
- 纯图片/视频媒体块。
- 表格和仅用于导航/操作的列表块。
- “点赞、在看、转发、作者、联系邮箱”等尾注。
- 过短且无法形成独立视觉语义的文本。

当有效正文段落超过 12 个时，在全文中均匀选取 12 个，而不是只取开头。

## 6. 兼容与异常规则

- 旧 draft 没有字段：使用 `standard`。
- 非法值：使用 `standard`，不返回 500。
- 视觉规划 LLM 失败：使用本地 fallback prompt，数量和锚点仍由后端决定。
- 单张 T2I 失败：跳过该张并继续下一张。
- 整批预算耗尽：停止后续图片调用，使用已成功图片继续文章。
- 用户配图与 AI 段落图冲突：沿用现有规则，用户配图优先。
- 题图失败：front matter 继续沿用首张正文图、原文图或项目默认题图的既有降级。

## 7. 非功能要求

- 并发：复用 `app/jobs.py` 默认最大 2 个 worker，不创建额外线程池。
- 数量：详细正文图硬上限 12。
- 超时：图片请求保持单次受控超时，整批预算 900 秒。
- 容量：单张解码/下载图片不超过 12MB，单篇 AI 图片批次不超过 64MB；响应和下载均使用累计字节限制。
- 日志：只记录模式、计数、异常类型，不记录 API key 或完整认证头。
- 存储：沿用 `assets/images/generated/<slug>/`，不新增数据库迁移。

## 8. 验收映射

| 验收项 | 产品证据 | 验证类型 |
| --- | --- | --- |
| A1 | 三表单 radio 卡片、默认状态、响应式 CSS | UI/Playwright |
| A2 | draft JSON 与 job payload | 单测/集成 |
| A3 | 四档调用数量和段落锚点 | 单测 |
| A4 | 12 张/900 秒/12MB/64MB 护栏与失败继续 | 单测/代码审查 |
| A5 | 旧改写率、原媒体、用户图、风格和写入链路 | 回归测试 |
| A6 | 任务阶段与完成 warning/success | 单测 |
| A7 | 测试矩阵和截图 | Harness |
| A8-A9 | 发布/回滚和安全检查 | 发布门禁/Git |

## 9. 非目标

- 不在风格页重复显示/编辑模式。
- 不做调用费用预估、取消、重试或断点续跑 UI。
- 不对历史文章补图。
- 不改变全局吉卜力风格锁。
